# 策略、准入与投资证据

本文解释稳定的策略权限和证据方法，不保存策略的当前预算、样本数、收益或上线状态。具体结论必须
绑定协议版本、代码/配置/数据指纹、目标数据库和机器报告；“latest” 文件名本身不保证报告仍有效。

## 实现、研究与准入是三件事

策略代码存在只说明系统能够计算它。历史回测通过允许继续研究，但不自动允许生成正式订单。
策略要影响正式预算，还必须通过当前证据政策、数据 readiness、确定性风控和用户确认。

稳定权限层级：

| 层级 | 用途 | 正式新增预算 |
|---|---|---:|
| 生产准入 | 规则冻结且满足生效中的证据政策 | 由组合与风控决定 |
| 前瞻影子 | 用自然未来数据挑战冻结规则 | 0 |
| 研究候选 | 回测、回放、消融与诊断 | 0 |
| 拒绝/失效 | 未通过预设门槛或已触发失效条件 | 0 |

状态必须来自当前策略 registry、配置、数据库和协议绑定，不从本文或旧报告推断。

## 策略族

QuantLab 代码包含以下研究方向：

- ETF 等权核心与主动轮动；
- Adaptive ETF 研究变体；
- A 股横截面、回撤修复与市场状态策略；
- 可转债双低与风险过滤；
- 纯量化、原始 LLM、统计概率、融合和门控策略的消融变体。

这些名称表示实现和研究谱系，不表示当前已准入。每个版本的事前候选、开发区间、留出、成本、
门槛和失败处理见对应 `*_PROTOCOL.md`、`*_PREREGISTRATION.md` 和 Postmortem。

## 证据梯子

```text
机制单测
  -> 点时历史回测 / 回放
  -> Walk-forward 与锁定留出
  -> 成本、基准、参数和市场状态压力
  -> 自然前瞻预测样本
  -> 独立现金、订单、成交和 NAV 的影子组合
  -> 足量到期后的区间、消融和准入决策
```

每一层回答的问题不同：

| 证据 | 可以说明 | 不能说明 |
|---|---|---|
| 单元/集成测试 | 规则按预期执行 | 策略赚钱 |
| Historical Demo | 产品链路可复现 | 实时可用或正式前瞻成功 |
| 历史回测 | 固定假设在该历史区间的表现 | 未来收益 |
| Walk-forward/留出 | 降低同区间调参偏差 | 消除所有选择偏差 |
| 概率成绩 | 预测相对类别基线的质量 | 组合含成本收益 |
| 影子 NAV | 冻结执行规则的自然组合结果 | 自动实盘资格 |
| 用户模拟 | 产品和用户决策结果 | 系统策略 Alpha |

## 历史研究最低合同

一份可用于审阅的历史结果至少要说明：

- 标的池如何在当时形成，上市、退市、ST 和停牌如何处理；
- 信号截止时间与标签可用时间；
- 成交时点、原始/复权价格语义、T+1、整手、涨跌停；
- 佣金、最低佣金、印花税、过户费和滑点；
- 连续资金曲线和现金约束；
- 可投资、同风险暴露的基准；
- 开发、embargo、验证、锁定留出和重复试验范围；
- 源码、配置、数据、协议和结果指纹；
- 失败、缺失和拒绝是否原样保留。

固定今天的资产池回看过去仍可能有成员选择偏差。历史股票池、ETF 可交易池和可转债池只有带点时
身份时才能降低幸存者偏差。

## 正式前瞻最低合同

正式样本必须同时满足：

1. 事前冻结的协议、候选、阈值和 horizon；
2. 服务器控制的数据摄取和 production namespace；
3. 对应交易日的 Provider selection、manifest 和 PIT pool；
4. 每个纳入字段 `available_at <= cutoff_at`；
5. 自然 Scheduler 来源，而非事后 backfill 或人工创建；
6. 样本、变体、影子账户、订单、成交和到期结果身份一致；
7. 旧样本不可回写，恢复过程单独标注；
8. 未满足时保持 blocked/unavailable，不补造成功。

恢复链可能产生可审计的恢复记录，但不能改写为首次自然窗口成功。Worker `completed` 也不能替代
readiness、字段覆盖或结果身份检查。

## 概率质量与交易价值分开

5/20 交易日概率使用 Brier、Log Loss、校准和类别基线评估。组合价值使用含成本收益、基准超额、
回撤、换手、风险暴露和区间评估。

概率更准确不一定提高收益，可能因为：

- 冻结交易阈值没有触发；
- 改变的交易不足；
- 避险同时放弃了更多上涨；
- 费用抵消了差异；
- 样本太少或类别不平衡。

因此 LLM 增量必须比较同期、同协议、同数据的纯量化、原始 LLM、统计模型、融合和完整系统。不能
把不同市场、不同池或不同成本的两条曲线直接相减。

## 组合准入

证据优先组合政策遵循：

1. 未准入策略默认预算为 0；
2. 主动策略必须与简单、低成本、可投资基准比较；
3. 组合层统一执行总暴露、单标的、行业、现金和相关性约束；
4. 数据新鲜度与可交易性在订单前重新检查；
5. LLM 可以提出反证或更保守建议，不能放宽硬规则或增加未授权预算；
6. 最终模拟订单仍需用户明确确认。

当前哪个策略获得预算应从生效配置、策略状态、证据政策和交易前检查读取，不从历史策略排名读取。

## 账户与成绩隔离

| 记录 | 目的 | 允许进入哪里 |
|---|---|---|
| 用户模拟账户 | 自由买卖和产品复盘 | 用户自己的时间线 |
| Historical Demo | 黑客松与产品演示 | 隔离 Demo 账本 |
| 研究回放 | 机制诊断 | 历史研究报告 |
| 正式影子账户 | 冻结策略的自然执行 | 绑定协议的影子 scorecard |
| 外部只读组合 | 手工/CSV 记录实际持仓 | 用户账本，不冒充券商数据 |
| Primary | 预注册自然样本 | 对应正式 scorecard |
| 宽样本研究 | 独立横截面协议 | 宽研究成绩，不并入 Primary |

用户采纳、产品使用事件、Demo 和人工导入都不能用来补正式训练或成绩。

## 动态验收路径

验收某个策略或模型时，记录目标数据库和观察时间，并检查：

```text
协议/版本
  -> code + config + data fingerprint
  -> experiment/cohort/sample identity
  -> Provider/PIT/cutoff provenance
  -> orders/fills/NAV/settlements
  -> baseline + cost + interval + ablation
  -> admission decision + failure reason
```

相关入口：

- `docs/AI_HANDOVER.md`：完整验收顺序；
- `AI_REVIEW_GUIDE.md`：对抗检查和输出要求；
- `data/reports/profitability-evidence-latest.json`：候选机器摘要，必须先验指纹；
- `src/quantlab/workflows/validation.py`、`forward_ablation.py`、`forward_experiment.py`、
  `shadow_trading.py`、`wide_forward.py`：主要编排；
- `src/quantlab/persistence/strategy_evidence.py`、`round5.py`、`wide_research.py`：主要仓储；
- 对应协议和测试：事前门槛、失败路径和污染边界。

最诚实的默认结论是：工程闭环、历史研究、自然前瞻和 Alpha 必须分别判定。没有足量自然到期证据
时，应明确写“尚未证明”，而不是用更多功能、更多 Agent 或更漂亮的历史曲线补足。
