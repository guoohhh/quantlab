# 项目总览

QuantLab 是面向个人投资者的可审计研究与模拟交易工作台。它解决的不是“让 AI 猜一只股票”，
而是把发现、研究、反证、风控、用户决定、模拟成交和复盘放进同一条可追溯链路。

## 系统服务谁

- 希望先模拟再行动的个人投资者；
- 需要 AI 帮助整理大量信息，但不愿把事实与风控交给模型的人；
- 想验证策略和 Agent 是否真的有增量，而不是只看一份漂亮报告的人。

系统不是教学平台、券商交易终端、收益保证产品或多人 SaaS。真实订单仍需用户在券商端完成。

## 核心问题

1. 数据在当时是否真实可见，是否带来源、时间和缺失原因；
2. 策略是否经过点时、成本、可投资基准和样本外检验；
3. 多 Agent 是否提供了新证据与反对意见，而不是重复表达；
4. 建议进入组合后会占多少资金、承担什么风险、违反哪些规则；
5. 用户最后做了什么，5/20 个交易日后结果如何，系统是否从错误中学习。

## 当前产品结构

五个一级决策工作区为 `今日`、`市场与发现`、`研究台`、`组合与交易` 和 `决策复盘`。
`专业空间` 与 `帮助中心` 位于“我的与工具”；`研究详情`、`专家圆桌` 和 `设置` 是带父级
归属的二级路由，不扩张一级决策导航。

右侧全局 AI 助手可感知当前页面、账户、标的、研究和订单上下文；复杂问题进入后台 Job，
切换页面不会把草稿或会话串到错误上下文。AI 形成的交易动作仍只是待确认草稿。

## 系统分层

```text
行情、财务、新闻、宏观、资金与持仓
  -> 版本化证据与点时身份
  -> 确定性指标、策略、成本和风险
  -> 多 Agent / LLM 解释、反证和概率
  -> 用户确认的模拟订单或外部手工记录
  -> 自然到期结果、成绩单和 Reflection
```

数据与确定性代码拥有事实和权限权威。LLM 可以提出假设、解释冲突和保守降级，但不能伪造数据、
放宽硬规则、自动确认订单或把研究结果写入正式成绩。

## 如何理解完成度

QuantLab 已形成较完整的工程与产品链路，但这不等于已经证明稳定 Alpha。以下结论必须分开：

- 页面和后台任务能运行：工程证据；
- 历史回测或 Historical Demo 有正收益：历史研究证据；
- 自然冻结的预测到期：前瞻样本；
- 含成本组合稳定优于可投资基准且区间显著：盈利增量证据。

当前实际状态不写在本文件。请用 `quantlab runtime-status`、生产数据库、任务 provenance 和匹配
当前源码指纹的 `data/reports/*-latest.json` 核验。

## 关键边界

- 用户模拟、系统影子、Historical Demo、外部只读账本和正式前瞻相互隔离；
- 正式样本不得回填或改写，恢复运行不能冒充首次自然窗口；
- 免费数据源无 SLA，字段不足或时间越界时保持 `unavailable`；
- `completed` Job 不等于数据完整或实验有效；
- 所有收益与预测展示都必须标注证据身份和限制。
