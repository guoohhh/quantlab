# 功能与用户使用流程

## 1. 前端总览

Streamlit 前端当前有 15 个一级页面。自动测试报告记录 24 个标签对象，是因为部分一级页面内部还有子标签。

| 一级页面 | 用户能做什么 | 结果是否能直接成为订单 |
|---|---|---:|
| 今日决策 | 看市场状态、建议总暴露、最近决策、计划最大损失和下一步 | 只汇总，不直接下单 |
| 市场雷达 | 看跨资产 20/60/120 日强弱、波动、宽度、风险偏好和可选行业热度 | 否 |
| 股票发现 | 搜索、自选、系统推荐、历史排名证据、批量深度会诊 | 推荐本身不能 |
| 候选擂台 | 对 2–6 个 ETF 用同标准多 Agent 研究、排名、去重和压力测试 | 否 |
| 多 Agent 研究 | 对单个 ETF 或股票生成完整研究、概率预测和 Reviewer 结论 | 还需组合层 |
| 专家圆桌 | 自选 2–8 位大师或专家，进行 1–3 轮讨论 | 明确不能 |
| 手工下单计划 | 生成三策略统一组合和手工执行清单 | 只有 `actionable` 可供再次核对 |
| 模拟盘 | 运行 ETF 五账户和 A 股三账户的前瞻影子交易 | 否，全部是假账户 |
| 证据中心 | 查看盈利证据、策略准入、概率消融和前瞻成绩单 | 否 |
| 历史盲测 | 匿名化历史节点、假下单并在未来结算 | 否 |
| 组合账本 | 管理风险画像、账户资金和手工交易记录 | 记录，不连接券商 |
| 学习状态 | 查看样本、模型版本、挑战、误差归因和漂移 | 否 |
| LLM 配置 | 选择 GPT 模型、推理强度和运行回放 | 否 |
| 审计报告 | 查看已保存决策并导出 Markdown/JSON | 否 |
| 一键 Demo | 真实雷达 → 自动候选 → 多 Agent → 报告下载 | 演示用途 |

## 2. 侧边栏 LLM 配置

用户可以在前端选择：

- 速度优先、平衡、质量优先预设；
- 默认 GPT 模型；
- 默认推理强度；
- 自定义模型名称；
- 高级模式下为每个 Agent 单独选择模型和推理强度。

API Key 只从本地 `.env` 读取，前端不会显示、回传或写入报告。

选择模型只改变研究调用方式，不改变硬风控、交易成本和策略准入结果。

## 3. 第一次使用的推荐流程

对于量化新手，建议不要一上来就运行最贵的批量 Agent。

### 第一步：检查环境

运行：

```powershell
quantlab doctor
```

它会检查 Python、数据工具、模型配置和本地运行条件。

### 第二步：打开前端

```powershell
streamlit run dashboard/app.py
```

### 第三步：先看市场雷达

确认：

- 数据源是否真实；
- 最新行情日期；
- 是否有降级；
- 当前市场偏风险开启还是风险关闭；
- 哪些资产相对更强。

### 第四步：看证据中心

先知道哪些策略已经准入，哪些仍是研究。不要因为某个页面出现候选，就假设系统建议买入。

### 第五步：再选择一种研究路径

- 已经有心仪股票：走“自选股票”流程；
- 不知道买什么：走“系统推荐”流程；
- 想看大类资产：走“ETF 雷达和擂台”流程。

### 第六步：最后才看手工下单计划

只检查 `actionable` 项，并再次核对当天券商行情。若是 `blocked` 或 `review_required`，不要把它解释成“系统暗示可以买”。

## 4. 流程 A：分析自己选择的股票

适合“我想看看贵州茅台、美的集团或宁德时代”的场景。

1. 在“股票发现”搜索名称或代码；
2. 加入自选池，可分组和写备注；
3. 在“我的股票池”中最多选 20 只做快速筛选；
4. 快速筛选计算因子、趋势、流动性、回撤、财务快照和相关性，不调用 LLM；
5. 从中明确选择最多 5 只进入“批量深度会诊”；
6. 系统逐只运行财务双源检查、多 Agent、五位投资大师、Bull/Bear、5/20 日预测和 Reviewer；
7. 查看决策卡、证据缺口和确定性估值区间；
8. 下载 Markdown 或 JSON 报告；
9. 若要考虑仓位，再进入组合规划器。

重要区别：

- 快速筛选输出的是研究优先级；
- 深度会诊输出的是研究结论；
- 组合规划器才决定是否有新增预算。

## 5. 流程 B：让系统推荐股票

系统不是只给一张总榜，而是并行使用五种风格：

| 风格 | 通俗含义 |
|---|---|
| 趋势质量 | 上涨不是一天暴冲，而是路径较稳定、量价较健康 |
| 价值质量 | 估值相对保守，财务质量和现金流不差 |
| 成长质量 | 盈利和业务成长有一定质量，不只追逐热门概念 |
| 回撤修复 | 经历回调后出现修复条件，而不是盲目抄底 |
| 高股息 | 股息和质量相对较好，偏防御 |

系统会轮询合并不同风格候选，再统一重排和相关性去重，避免某一种风格占满列表。

推荐结果会惩罚：

- ST；
- 高波动；
- 20 日过度延伸；
- 数据缺失；
- 流动性不足。

它依然只是“优先研究名单”，需要用户选择后再进入深度会诊。

## 6. 流程 C：分析 ETF 和大类资产

1. 在“市场雷达”看股票、黄金、海外和债券的相对强弱；
2. 选择 2–6 个领先 ETF 进入“候选擂台”；
3. 每个候选运行相同多 Agent 和 5/20 日预测；
4. 系统生成统一排名；
5. Reviewer、否决闸门和人工复核先过滤；
6. 对高度相关候选去重；
7. 对入围等权假设组合计算波动、VaR、CVaR、回撤和情景冲击；
8. 该假设组合只用于比较，不产生订单；
9. 真正订单仍来自“手工下单计划”中的生产核心政策。

## 7. 流程 D：召开专家圆桌

专家圆桌的目标不是让大师替你拍板，而是暴露分歧和新问题。

操作方式：

1. 先选择一份已经保存的研究报告；
2. 系统冻结报告中的价格、因子、财务、新闻、Agent、概率和决策轨迹；
3. 用户自选 2–8 位参与者；
4. 选择 1–3 轮讨论；
5. 同一轮角色并行发言，避免固定发言顺序造成锚定；
6. 第二轮起必须回应上一轮最强论点；
7. 主持人汇总共识、分歧、最强多空论点、证据缺口和下一步。

可选角色包括 Buffett、Munger、Graham、Fisher、Lynch 以及其他分析和风险角色。

圆桌输出固定带有 `formal_decision_changed=false`。它不能修改正式决策、风控或订单。

## 8. 流程 E：生成手工下单计划

组合规划器把 ETF、A 股和可转债候选放入同一资金账户，而不是让三条策略各说各话。

输出可能出现：

- `actionable`：当前规则允许，仍需用户核对后手工执行；
- `blocked`：硬风险或数据新鲜度失败；
- `review_required`：关键证据缺失或冲突；
- `below_minimum`：买不起一手或金额太小。

当前证据政策下：

- 45% ETF 等权核心可在新鲜行情下产生订单；
- 主动 ETF 预算为 0；
- 未准入 A 股策略预算为 0；
- 可转债预算为 0；
- LLM 不能把这些 0 预算改成正数。

## 9. 流程 F：使用模拟盘验证未来表现

模拟盘不是历史回测，而是站在真实当日向前记录。

ETF/基准五账户用于比较不同决策层：

- 纯策略或基准；
- 当前完整系统；
- 其他固定对照。

A 股三账户用于比较：

- 固定池等权；
- 确定性系统排名；
- 完整多 Agent 审核。

模拟盘执行：

- T 日信号冻结；
- 下一个真实交易日开盘假成交；
- 股票 T+1；
- 停牌和一字涨跌停；
- 100 股整手；
- 真实成本与滑点。

模拟盘的意义是积累不可回写的前瞻证据。

## 10. 流程 G：历史盲测和假下单

历史盲测会：

- 自动抽取过去的日期；
- 在研究时隐藏标的身份和日期；
- 只使用当时可见数据；
- 运行真实 LLM 角色；
- 按 T+1 开盘假成交；
- 最后揭示未来收益。

它比普通回测更接近“当时真的不知道答案”，但样本仍来自历史，不能替代未来模拟盘。

## 11. 今日决策中心

“今日决策”把复杂输出压缩成：

- 当前市场状态；
- 风险偏好；
- 建议总暴露；
- 新增买入数量；
- 减仓/卖出数量；
- 最大计划损失；
- 最近决策卡；
- 今日手工清单；
- 下一步待办。

它是摘要页，不重新发明一套决策逻辑。

## 12. 证据中心

证据中心用于回答：

- 策略是否经过成本一致的样本外验证；
- 是否跑赢简单可投资基准；
- 统计超额是否可信；
- 默认组合为什么选择等权核心；
- Adaptive V1/V2/V3 为什么没有上线；
- A 股 V3 为什么有正收益仍然失败；
- LLM、统计模型和最终融合哪个概率更好；
- 前瞻账户积累了多少样本。

如果用户只看收益数字而不看这里的状态和边界，很容易误解系统。

## 13. 学习状态

学习页面展示：

- 5 日和 20 日样本数量；
- ETF、股票、可转债资产域；
- 当前模型和历史版本；
- `promoted`、`rejected`、`challenge_pending` 等状态；
- Brier 和 Log Loss；
- 误差归因；
- 线上漂移；
- 统计模型实际融合权重。

当前 legacy 统计模型的生产融合权重已经降为 0，等待真正前瞻冠军挑战完成。

## 15. API 能力分组

FastAPI 当前有 73 个路由，覆盖：

- 健康与引擎状态；
- 市场雷达、证券搜索和股票发现；
- 单股与批量多 Agent；
- 圆桌会议；
- 回测与历史盲测；
- 自选池；
- 信号与预警记录；
- 风险画像、资金、交易账本和组合计划；
- ETF/A 股模拟盘；
- LLM 配置与回放；
- 学习训练、事件和周期；
- 证据和报告。

如果配置 `QUANTLAB_API_TOKEN`，所有 `/api/` 请求必须携带本地令牌。未配置时只应绑定本机回环地址。

## 16. 黑客松演示流程

最稳定的现场演示顺序：

1. 运行 `quantlab doctor`；
2. 展示质量门禁摘要；
3. 打开“市场雷达”确认真实数据和截止日；
4. 进入“一键 Demo”；
5. 自动选择候选；
6. 展示不同模型路由的多 Agent 研究；
7. 展示决策卡、概率预测、Reviewer 和可复算轨迹；
8. 下载 Markdown/JSON 报告；
9. 打开“证据中心”，主动展示失败策略和默认 ETF 核心的选择理由；
10. 展示数据陈旧时订单被阻断，证明系统不会为了演示而伪造可执行建议。

这条演示线能同时体现产品体验、AI 能力、金融纪律和审计性。
