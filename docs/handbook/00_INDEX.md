# QuantLab 手册导航

## 先看结论

QuantLab 的目标不是“让几个 AI 猜涨跌”，而是建立一条有证据、有纪律、能复盘的投资决策流水线：

```text
真实数据
  → 确定性指标与策略
  → 多 Agent 分工研究与相互反驳
  → 概率预测
  → 硬风控与组合约束
  → 手工下单建议
  → 未来结果结算
  → 模型评估与再训练
```

当前状态可以用三句话概括：

1. **工程第一版已成形。** 前端、CLI、API、SQLite、回测、模拟盘、报告和学习闭环均有真实代码与测试。
2. **默认生产策略很克制。** 只有 45% 六 ETF 等权核心获得历史协议支持；陈旧行情会直接阻止订单。
3. **主动盈利能力仍未证明。** 主动 ETF 没跑赢可投资的 ETF 等权基准，A 股 V3 未通过统计门槛，LLM 尚无交易收益增量证据。

## 状态词典

项目会反复使用下面四类状态。它们不是文字装饰，而是决定策略能不能影响订单的权限边界。

| 状态 | 通俗解释 | 能否产生新增订单 |
|---|---|---:|
| 生产核心 / `historically_supported` | 规则已经冻结，并有与实际执行协议一致的历史证据 | 行情新鲜且风控通过时可以 |
| 研究 / `research_only` | 可以展示、分析、回测，但证据不够上线 | 不可以 |
| 影子 / `shadow` | 按真实时间向前记录假账户，用未来数据检验，不动真钱 | 不可以 |
| 阻断 / `blocked` | 数据陈旧、硬风险或规则冲突，系统明确拒绝执行 | 不可以 |

`review_required` 表示关键证据缺失或冲突，需要人检查；它也不能被当成可直接下单。

## 哪些资料最权威

如果不同旧文档出现口径差异，按下面优先级判断：

1. 当前代码和配置；
2. `data/reports/*-latest.json` 的机器可读报告；
3. 本手册的 2026-07-15 快照；
4. 根目录较早的研究协议与复盘文档；
5. README 中的历史更新记录。

其中最重要的三份机器报告是：

- `data/reports/quality-gate-latest.json`：工程质量状态；
- `data/reports/etf-core-protocol-validation-latest.json`：默认 ETF 核心的同协议验证；
- `data/reports/profitability-evidence-latest.json`：策略、LLM、统计模型和前瞻证据汇总。

## 阅读时需要一直记住

- 历史赚钱不等于未来会赚钱。
- “模型预测更准”不等于“交易一定赚得更多”。
- “有 18 个 Agent”不等于“18 份意见就是真相”。
- “策略有正收益”不等于“跑赢了一个同样可投资的简单基准”。
- “回撤较小”不等于“没有风险”。
- 任何 `actionable` 订单也仍需用户在下单前核对最新价格、公告、停牌和涨跌停。
