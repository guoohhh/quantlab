# 现状、不足、评分与路线图

## 1. 暂停开发时的整体判断

QuantLab 已经跨过“概念 Demo”阶段，形成了可运行系统：

- 有真实数据接入；
- 有确定性量化和回测；
- 有多 Agent 和真实 LLM 路由；
- 有前端、CLI、API 和 SQLite；
- 有 A 股特有交易规则；
- 有组合规划、模拟盘和学习闭环；
- 有质量门禁和外部 AI 审阅入口；
- 有真实失败证据和策略准入隔离。

但它还没有跨过“主动盈利能力被充分证明”阶段。

当前最合适的定位是：

> 一个工程完成度较高、研究纪律较强、可以参加黑客松并辅助人工投资研究的第一版系统；默认只允许克制的 ETF 核心，主动 Alpha 和 LLM 增益仍需前瞻验证。

## 3. 当前评分应该怎么看

最新机器质量报告故意没有自评分：

- `self_assigned_score = null`
- 工程质量门禁：通过
- 主动盈利证据：`preliminary 60/100`

内部人工判断可以分三种视角：

| 视角 | 合理区间 | 原因 |
|---|---:|---|
| 黑客松产品/工程评审 | 93–95 | 功能闭环完整，AI、金融、审计、前端和演示性都较强 |
| 严格量化研究评审 | 88–92 | 证据治理好，但主动 Alpha、前瞻样本和资产池点时性仍不足 |
| 综合判断 | 92–94 | 已是高质量第一版，但不能诚实保证“稳95” |

这不是正式评分，也不保证其他 AI 或评委一定同意。

如果有人给 95 分以上，理由应该是防泄漏、交易真实性、风控、失败证据保留、多 Agent 治理、工程质量和产品闭环，而不应该只是功能很多或历史收益数字漂亮。

## 4. 为什么现在不能说“稳95分”

### 4.1 固定六 ETF 存在成员选择偏差

当前六只 ETF 是今天冻结的资产池，再拿回 2015 年测试。虽然所有标的覆盖了测试区间，但系统没有证明 2015 年站在当时能事前选择完全相同的六类代表 ETF。

要补齐，需要版本化的 ETF 可交易池、上市时间、流动性和类别选择规则。

### 4.2 主动 ETF 没跑赢简单等权

主动 ETF 有正收益，也跑赢沪深300，但落后同一资产池等权。这意味着复杂策略当前没有证明增量价值。

### 4.3 LLM 没有证明交易收益增量

原始 LLM 的短样本概率质量较弱，早期 LLM 优先闸门还曾伤害收益。现在的策略主导架构更安全，但模型驱动减仓次数为 0，收益和纯策略相同。

需要至少一个冻结前瞻规则，在足量到期样本中证明概率更好、阈值确实触发、收益或回撤有增量，而且不是靠减少所有交易获得表面改善。

### 4.4 A 股主动策略尚未准入

A 股 V3 有正收益和正 Rank IC，但 Bootstrap 证据不够。

全市场回放使用点时分层样本，不是每天穷举全部上市公司；30 个样本中也没有抽到最终退市股。

### 4.5 可转债证据明显不足

有策略和风控代码，但没有点时全市场数据、长区间成本后 OOS 和前瞻成绩单。

### 4.6 前瞻样本需要真实时间

模型至少需要 30 个线上到期样本才适合做漂移和稳定性判断。历史回放可以加速发现错误，但不能伪造未来。

### 4.7 免费数据源没有 SLA

接口可能失败、限流或改变字段。系统会降级，但真实使用体验仍受外部源影响。

### 4.8 真实持仓尚未自动盯市

手工交易账本保存用户录入的成交价，尚未每天自动按最新价格更新真实持仓盈亏。

### 4.9 平台化能力仍有缺口

- 长任务统一后台 job；
- 进度、取消和幂等；
- 通知中心；
- 决策 profile 快速重评；
- 统一版本化 AnalysisContextPack；
- 受限工具型 Chat；
- QuantLab Skill/MCP Gateway；
- 通用用户策略实验室。

### 4.10 测试覆盖率还不是极高

72.49% 已通过当前 71%门槛，关键金融模块有更高单独门槛；但 CLI、部分外部适配器和编排工作流仍有覆盖缺口。

## 5. 当前风险清单

| 风险 | 可能后果 | 当前缓解 |
|---|---|---|
| 历史过拟合 | 回测好、未来差 | 预注册、留出、Walk-forward、失败保留 |
| 幸存者偏差 | 高估股票策略 | BaoStock 点时市场、退市前行情、训练准入 |
| 数据陈旧 | 用旧价格生成错误订单 | 1个工作日硬闸门 |
| LLM 幻觉 | 编造财务或错误解释 | 结构化输入、事实源、Reviewer、确定性计算 |
| LLM 超时 | 研究链路缺角色 | 多 Provider 回退、零置信降级、人工复核 |
| 小账户成本 | 小额频繁交易吞噬收益 | 最低佣金、整手、最低金额、低换手核心 |
| 策略互相抢预算 | 总仓位失控 | 统一组合层和证据优先政策 |
| 把概率准确当盈利 | 错误上线模型 | 策略验证与预测验证分离 |
| API Key 泄漏 | 安全与费用风险 | 本地.env、忽略提交、导出脱敏、扫描 |
| 用户过度依赖 | 把研究当保证 | 手工执行、状态边界、风险声明 |

## 6. 达到稳定95分最关键的四个条件

### 条件一：至少一个主动策略形成独立增量证据

不是只要正收益，而是需要：

- 跑赢同样可投资的基准；
- 成本和 1.5/2 倍成本下仍成立；
- 统计区间不再明显跨 0；
- 多个市场状态不依赖单一年份；
- 前瞻影子账户没有严重退化。

### 条件二：完成模型前瞻消融

每个 5/20 日周期至少积累 30 个以上到期样本，固定比较纯策略、原始 LLM、统计模型、最终融合和模型门控交易账户。必须分别证明概率质量和交易增量。

### 条件三：补齐 A 股全市场策略验证

- 更接近全市场每日 Top-K；
- 点时证券池；
- 退市与 ST 覆盖；
- 同暴露基准；
- 行业和市值中性；
- 稳定 Rank IC；
- 成本后分散组合；
- 新版本不得重复使用已看过的 2023–2025 作为独立验证。

### 条件四：通过外部对抗审查

让独立 AI 或人工从量化研究、金融风控、Python 架构和黑客松产品四个视角审阅，修复所有高严重级别问题，并确保文档声明与机器报告一致。

## 7. 推荐后续路线图

### P0：先积累真正的前瞻证据

这是最影响“能不能赚钱”的工作。

1. 修复和稳定每日数据抓取；
2. 每个交易日运行 `daily-cycle`；
3. 保持 ETF 和 A 股影子账户不可回写；
4. 自动结算 5/20 日预测；
5. 记录数据源、模型、阈值和实际成交可行性；
6. 每满 10、20、30 个到期样本生成固定成绩单；
7. 不因为短期结果修改旧账户规则。

### P0：设计 A 股 V4

V4 可以吸收 V3 的真实失败：

- 风险开启时才允许股票卫星；
- 风险关闭时使用现金、国债或零股票预算；
- 避免单股高集中；
- 使用分散 Top-K 但重新设计排序和相关性约束；
- 把市场状态和选股规则同时冻结；
- 2023–2025 已经是已见开发数据，不能再当独立验证；
- 新的确认只能来自 2026 之后前瞻样本。

V4 开发前必须先写协议，不能看完结果再定门槛。

### P0：建立点时 ETF 资产池

需要保存每只 ETF 上市日期、历史可交易状态、成交额和规模、同类产品选择规则、类别代表切换，以及海外 ETF 溢价和交易时差风险。

这样默认核心才能从“今天六只标的的历史回放”升级为“历史每一天都能事前构造的资产池”。

### P1：统一 AnalysisContextPack

把 quote、K线、技术、财务、新闻、持仓和宏观块统一记录状态、来源、时间戳、`available_at`、fallback、缺失原因和质量限制。

### P1：后台任务与运行拓扑

研究、擂台、历史盲测和训练应统一成：

```text
submit → job_id → 进度/事件 → 完成/失败/取消 → 结果
```

需要数据库 claim、幂等键、取消和重试，避免同步页面长时间卡住。

### P1：用户价值功能

- 真实持仓自动盯市；
- 晨报/晚报；
- 本地、邮件或飞书通知；
- 预警去重、冷却和静默时段；
- 保守/平衡/进取 profile 对同一冻结报告快速重评；
- 更清晰的“我今天该做什么”待办。

### P1：可转债证据

- 点时可转债证券池；
- 历史强赎、评级、余额和停牌；
- 真实成本；
- 退市和到期处理；
- Walk-forward；
- 前瞻账户。

### P2：开源金融模型

只有数据治理和前瞻基线稳定后，才进入指令数据构建、LoRA/QLoRA、本地推理、商业 LLM/统计模型/微调模型盲测，以及模型注册与回滚。

### P2：平台化

- QuantLab Skill；
- 只读和回测优先的 MCP Gateway；
- 通用策略实验室；
- 桌面打包；
- 更完整的 Chat 和会话记忆。

## 8. 什么工作不应该做

- 不要重新使用同一留出集，直到得到满意结果；
- 不要为了提高分数修改盈利证据机器评分；
- 不要让 LLM 绕过零预算策略；
- 不要先训练大模型再补数据治理；
- 不要复制非商业许可证参考项目源码；
- 不要用 Demo 数据冒充真实行情；
- 不要用更多页面数量掩盖策略没有增量。

## 9. 暂停点建议

现在适合暂停并做三件事：

1. 用本手册完整走读系统；
2. 让其他 AI 按 `AI_REVIEW_GUIDE.md` 做独立审阅；
3. 决定下一阶段是优先积累前瞻证据，还是先补平台体验。

从“赚钱能力”目标看，优先级应是前瞻证据、A 股 V4 和点时 ETF 资产池，而不是继续增加 Agent 数量。

## 10. 最终结论

QuantLab 已经具备高分黑客松项目所需要的多数元素，也比普通“AI 荐股 Demo”更诚实、更可审计。

它还不能稳95分的原因不是功能少，而是金融证据需要时间和独立样本。

下一阶段最重要的工作，不是让系统说得更像专家，而是让固定规则在未来真实数据中反复接受检验。
