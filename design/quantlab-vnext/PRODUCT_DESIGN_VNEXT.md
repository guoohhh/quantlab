# QuantLab vNext 产品体验审计与设计方案

> 版本：2026-07-20
>
> 定位：面向有一定经验的个人投资者；纯新手通过帮助中心理解术语与流程。
>
> 视觉版本：Professional Workbench 03 · Evidence Trace / Quiet Signal。
>
> 本文先做产品判断，再谈页面。高保真原型位于 `prototype/index.html`，未改写生产前端。

## 1. 核心结论

不建议保留现有“五入口 + 普通/高级模式切换”。

推荐的产品模型是：

```text
五个稳定目的地
今日 / 市场与发现 / 研究台 / 组合 / 复盘

上下文工作区
标的研究 / 交易前检查与确认 / 单笔决策详情

跨页面工具
全局搜索 / Chat / 动态中心 / 帮助

独立专业空间
数据与运行 / Agent 与模型 / 证据与实验 / 全局审计
```

最重要的变化不是少一个导航项，而是从“按功能模块找页面”改为“围绕一项投资决策连续工作”。

研究台不是空白输入页，而是活跃论文、版本变化、证据缺口、自选和后台研究队列。用户再从研究台、搜索、市场、持仓或历史决策进入对象工作区。Chat 绑定当前报告，模拟订单从研究或组合打开检查抽屉，完成后回到组合与复盘。

### 1.1 默认用户与专业密度

默认用户已经理解持仓、基准、回撤、估值分位、行业暴露和订单状态。主界面可以直接使用这些术语，不增加“小白 / 专业”模式切换；解释、术语说明和首次使用路径统一进入帮助中心。

专业感不来自暴露更多内部后端名词，而来自：市场时点、可筛查对象、原始事实、论文变化、组合约束、订单账本、证据状态和完整决策留痕。Agent、实验与审计保持可达，但不替代投资分析本身。

## 2. 本轮如何体验和核验

### 2.1 阅读范围

本轮交叉阅读了：

- `PRODUCT_STRATEGY.md`；
- `docs/handbook/`；
- `dashboard/app.py`、`dashboard/product_ui.py`、`dashboard/ui_foundation.py`；
- 当前 SQLite、最新质量报告、运行/数据状态和 Historical Demo。

权威层级采用当前文档本身的约定：产品方向以 `PRODUCT_STRATEGY.md` 为准；价格、订单、证据、权限和账户隔离以后端代码与测试为准；当前状态由配置和机器报告复核。本设计不依赖 `my-system/` 外的交接或决策文档。

### 2.2 亲自体验

使用当前 `data/quantlab.db` 的隔离快照启动 Streamlit，避免污染生产账本，并完成：

1. 桌面 1440px 逐页走查五入口；
2. 窄屏 390px 逐页走查；
3. 在隔离快照中创建用户模拟账户；
4. 尝试对 `sh510300` 运行交易前检查；
5. 展开并运行冻结 Historical Research Demo；
6. 检查空、降级、错误、通知和后台任务状态；
7. 只读统计当前关键表。

### 2.3 实测结果

- 一个残留 Streamlit 实例直接暴露 `ModuleNotFoundError: No module named 'dashboard'` 框架错误页，没有产品级错误承接。
- 正确启动后，普通模式可以访问首页、行情与发现、AI 研究、模拟交易、我的。
- 当前 Live readiness 有多项阻断；行情与资金不能形成可操作状态。
- 创建模拟账户成功，但交易前检查只返回“交易前检查未完成，请检查行情、交易日和账户约束”，没有告诉用户具体缺口、恢复条件或还能做什么。
- Historical Demo 能完成研究、模拟订单、成交与盈亏闭环，并保持 `research_only` 隔离。
- 窄屏主要是把桌面内容纵向堆叠，顶部五入口换行；它“能显示”，但不是围绕窄屏任务重新组织。

## 3. 当前产品值得保留的基础

现有系统不是缺少能力，而是能力没有被组织成一个成熟产品。

应保留并强化的部分：

1. **确认权清楚。** AI 不自动替用户下单，模拟交易不连接券商。
2. **数据诚实。** 缺失、陈旧、部分可用和不可用不会用样例值掩盖。
3. **真实交易约束。** 整手、T+1、停牌、涨跌停、费用和滑点进入确定性规则。
4. **研究可追踪。** ContextPack、证据、模型、Decision Run、用户采纳和 Reflection 已有后端基础。
5. **长任务基础存在。** Job、取消、安全重试、通知和幂等已经实现。
6. **证据隔离明确。** Historical Demo、用户模拟、旧系统模拟/影子与正式前瞻表有独立边界。
7. **空结果被允许。** `watch`、`hold`、`review_required`、空候选和无订单都是合法结果。

这些不是“高级功能”，而是 QuantLab 的信任基础。新设计让普通用户在需要时理解它们，同时不必先学习内部术语。

## 4. 真实用户视角的体验审计

### 4.1 P0：导航分类维度混乱

现有五入口同时混用了三种分类方式：

- “行情与发现”是内容域；
- “AI研究”“模拟交易”是流程动作；
- “我的”是账户归属，但实际塞入投资论文、真实只读组合、任务、通知、Chat、数据源、持续运行和正式成绩。

用户需要在不同页面之间重新输入或重新定位对象，研究、追问、下单、持仓和复盘不能像一条连续链路一样工作。

设计决策：用“今日、发现、组合、复盘”作为稳定目的地；研究和下单成为附着于标的、账户和决策的上下文工作区。

### 4.2 P0：AI 研究以工具为中心，不以标的为中心

当前 AI 研究首屏是代码输入、日期和“生成研究报告”。用户看不到标的基础信息、已有版本、数据状态或来自持仓/发现的上下文。

Chat 也先要求创建会话，而不是自然地绑定当前研究报告。

设计决策：研究页固定证券身份、行情时间、数据质量、报告版本和账户上下文；Chat 常驻右侧并自动绑定 `symbol + effective_as_of + run_id + ContextPack`。

### 4.3 P0：研究到交易的连续性不足

当前模拟交易是独立一级页面。用户先进入交易页，再选择操作、标的和数量，然后运行检查。这个顺序容易鼓励“先想交易，再补研究”。

设计决策：从研究页或持仓打开订单草稿；同一抽屉内完成“订单 → 确定性规则与研究参考 → 用户独立确认”。交易后自动回到组合中的订单生命周期。

“AI 交易前检查”改名为“交易前检查”。确定性规则拥有事实与权限优先级，AI 研究只作为可解释参考。

### 4.4 P0：状态优先级会掩盖更重要的系统事实

当前首页先判断是否存在模拟账户；“无账户”可以盖住数据与运行服务未就绪。实际生产状态正是“无账户 + readiness 阻断”，用户首先看到的却只是创建账户。

设计决策：状态改为正交维度，不再压缩成一个页面状态：

| 维度 | 示例 |
|---|---|
| 数据 | fresh / stale / partial / unavailable |
| 任务 | queued / running / waiting / failed / completed |
| 权限 | allowed / review_required / blocked |
| 来源环境 | live / user_simulation / external_record / legacy_shadow / formal_shadow / historical_demo |

首页可以同时呈现“尚无账户”和“生产数据降级”，并明确两者分别影响什么。

### 4.5 P0：错误信息不能帮助用户恢复

交易前检查实测失败时，只显示一条泛化错误。用户不知道是休市、行情陈旧、主数据缺失、现金不足还是服务未运行，也不知道订单是否创建。

设计决策：每个失败状态必须回答：

1. 发生了什么；
2. 没有发生什么；
3. 哪些内容仍可查看；
4. 当前被禁止的动作；
5. 恢复条件；
6. 下一步入口。

例如：

> 当前行情截至 7 月 17 日 15:00，不能用于 7 月 20 日的当日模拟成交。订单尚未创建，账户没有变化。你仍可查看最近成功研究，等待数据刷新后重新检查。

### 4.6 P1：首页仍像功能与状态目录

当前首页同时出现账户、论文、任务、待办、风险、AI 建议、订单、通知、数据状态、正式实验边界和 Demo。内容都重要，但没有根据用户当前是否需要行动建立足够强的优先级。

设计决策：首页只回答三个问题：

1. 现在是否需要我处理什么；
2. 账户和持仓发生了什么变化；
3. 下一项值得继续研究的对象是什么。

专业运行状态只用一条清楚的可点击状态带呈现；Historical Demo 移入专业空间。

### 4.7 P1：视觉层级仍是“Markdown + 表单 + 表格”

当前界面主要依赖大标题、`st.subheader`、指标、蓝色信息块和表格。页面信息很多，但缺少对象层级、品牌节奏、空间关系和连续视觉线索。

设计决策：

- 页面标题从巨大的 Markdown 标题收敛为对象标题与任务标题；
- 使用“证据线”图形语言串联来源、判断、订单和结果；
- 降低卡片数量，用边界、留白和分组建立层级；
- 图表以解释问题为目的，不把所有指标做成 KPI 卡；
- 状态不只用颜色，还使用文字、图标、位置和权限变化。

### 4.8 P1：窄屏只是堆叠，不是重新编排

当前窄屏顶部五入口换成两行，长内容继续顺序下排，交易和研究的重要动作容易被淹没。

设计决策：窄屏使用四项底部导航；研究页固定“追问 / 创建模拟订单草稿”；Chat 和订单检查成为全屏 sheet；表格转换为持仓卡片，不依赖横向滚动。

### 4.9 P1：专业模式不应是全局界面切换

“普通模式 / 高级审计模式”会制造两套导航，也让用户难以判断当前对象的证据和全局实验之间的关系。

设计决策采用三层渐进展开：

1. 默认层：日期、证据质量、反证、失效条件和权限始终可见；
2. 对象层：“证据与审计”展示引用、ContextPack、模型和 Decision Run；
3. 全局层：独立专业空间展示数据、Agent、实验、影子账户、运行和全局审计。

## 5. 当前能力与数据状态

核验时间：2026-07-20；生产库以只读方式统计。

| 能力 | 代码能力 | 当前生产数据 | 设计含义 |
|---|---|---|---|
| 用户模拟账户/订单/成交/持仓 | 已实现 | 全部 0 | 空状态必须成熟；不能用 Demo 充填 |
| Chat 会话/消息/动作草稿 | 已实现 | 全部 0 | Chat 从上下文自然开始，不先建空会话 |
| 通知 | 已实现 | 2 条未读任务完成通知 | 进入全局动态中心；统一中英文文案 |
| 决策任务 | 已实现 | 0 | 无任务是正常状态，不强造待办 |
| 后台 Job | 已实现 | 2 条 `trusted_data_refresh`，均 completed | 用用户语言表达“可信数据刷新已完成” |
| API / Worker / Scheduler / Notification Worker | 已实现 | 四个组件当前均为 stopped | “已配置”与“正在运行”必须分开；新后台任务可能只能排队 |
| 启用的 Schedule | 已实现 | 19 个 | 不能因为 schedule enabled 就声称每日任务会自动执行 |
| 正式 forward protocol/run/sample/milestone | 已实现表结构 | 全部 0 | 不能把历史预测或旧学习样本当正式前瞻证据 |
| Round5 正式七消融影子账户 | 已实现 | 0 | 显示“尚未启动”，不能声称已有正式影子表现 |
| 旧 `paper_accounts` 系统模拟/前正式影子 | 旧能力存在 | 8 账户、22 pending 订单、0 trades、12 个 100,000 NAV 快照 | 单独标为 legacy；不能与正式影子合并 |
| Historical Demo | 已实现且可运行 | 独立 Demo 库形成 1 账户、1 filled 订单、1 fill、1 position、1 snapshot | 使用贯穿全页的“历史演示 · 仅研究”环境标识 |
| Live 数据与 readiness | 已实现失败关闭 | 最近刷新失败；正式点时股票池为 0 | 保留最近成功内容，但关闭依赖当前行情的操作 |
| 最新质量门禁 | 报告曾 passed | 当前源码指纹已变化，readiness 不接受为当前通过 | 专业空间显示“需重新验证”，不能显示当前就绪 |

额外发现：

- 首页正式实验摘要读取 `accounts`，而 shadow scorecard 实际返回 `variants`；正式实验启动后可能错误显示影子账户为 0。生产当前本来为 0，但实现前应修正契约。
- 生产通知标题是中文，正文仍是 `Background task trusted_data_refresh completed.`，需要统一本地化。
- legacy `forecast_predictions` 与 `learning_samples` 有历史记录，但 formal forward 表为 0；所有产品文案必须保留“历史/旧研究输出”和“正式前瞻证据”的区别。
- 数据库自身 `quick_check=ok`、外键违规为 0，共 137 张业务表；“数据库完整”不等于“当前行情与运行服务就绪”。
- 最后成功数据仍可读取：491 条生产交易日历、5,536 个 A 股证券主数据、5,203 个行业归属标的；但最近 BaoStock 日历刷新超时，后续主数据与行业刷新被 single-flight 阻断，四个 `minimum_ready` 均为 false。
- 2026-07-20 在可信日历中是交易日，但核验时尚无当天 refresh、Provider selection 或生产点时池。界面必须同时显示“最近一次尝试失败”和“最后一次成功数据”，不能只给一个红色不可用标签，也不能用历史记录数冒充本轮成功。

## 6. 设计原则

### 6.1 先回答，再展开

先告诉用户当前判断、影响和权限，再展开证据、Agent 和审计。不是先展示内部流程。

### 6.2 对象附着优先

研究、Chat、订单、持仓和复盘都附着于证券、账户、报告或 Decision Run；尽量避免无上下文的空白页面。

### 6.3 状态改变权限

`stale`、`blocked`、`research_only` 不只是徽标。它们必须直接改变按钮、确认路径、数据引用和可写范围。

### 6.4 硬规则与 AI 分层

数据、身份、交易日、费用、仓位和风险规则拥有确定性权限；AI 解释、找反证、提出软建议和草稿，不能放宽硬闸门。

### 6.5 失败关闭，但不把用户赶走

缺失当前行情时关闭成交，不等于整页不可用。用户仍可查看上次报告、理解缺口、继续非操作性追问或等待后台刷新。

### 6.6 不强制教学

帮助中心围绕当前任务和状态组织，不做课程、考试、风险画像或强制新手流程。

## 7. 完整信息架构

### 7.1 一级目的地

| 入口 | 回答的问题 | 主要内容 |
|---|---|---|
| 今日 | 现在是否需要我做什么 | 待确认、账户摘要、持仓/论文变化、研究线索 |
| 市场与发现 | 市场处于什么状态，什么值得继续研究 | 市场脉络、资金口径、行业、异动、自选、研究线索 |
| 研究台 | 哪些论文、证据和任务正在变化 | 活跃论文、版本变化、七证据域、研究队列、自选与历史报告 |
| 组合 | 我的账户和订单怎么样 | 用户模拟、外部只读记录、持仓、现金、盈亏、订单、成交、费用 |
| 复盘 | 当时为什么做，后来怎样 | 研究版本、用户选择、订单、结果、基准、失效条件与 Reflection |

### 7.2 上下文工作区

#### 标的研究

- 固定证券身份、行情时间、数据状态和研究版本；
- 当前研究判断；
- 支持与反对证据；
- 失效条件；
- 账户与组合影响；
- 概率及证据等级；
- 证据账本与对象级审计；
- 绑定当前报告的 Chat；
- 创建模拟订单草稿。

#### 交易前检查与确认

同一侧栏完成：

```text
订单草稿
→ 服务器行情与确定性规则检查
→ AI 研究参考和组合影响
→ 用户独立确认
→ pending / filled / rejected / expired
```

#### 单笔决策详情

展示“证据 → AI 判断 → 用户选择 → 订单与成交 → 后续结果 → 复盘”的完整链路。

### 7.3 跨页面工具

#### 全局搜索

搜索股票、ETF、持仓、历史决策和任务。选择资产后直接进入研究工作区。

#### 动态中心

合并但不混淆：

- 待处理：需要用户判断或确认；
- 通知：已经发生的结果或变化；
- 后台运行：排队、处理中、等待、失败、取消和完成。

#### Chat

顶部入口只负责恢复最近会话；发起新会话必须继承或选择上下文。Chat 中的订单、预警和论文修改只生成草稿。

#### 帮助

既有全局帮助中心，也在日期差异、概率、账户徽标、硬阻断和历史演示旁提供上下文帮助。

### 7.4 专业空间

四个分区：

1. 数据与运行；
2. Agent 与模型；
3. 证据与实验；
4. 审计与 Decision Run。

进入后使用独立空间名称、深色环境和账户/证据边界表，不仅是侧栏切换。

## 8. 核心用户路径

### 8.1 发现到复盘

```text
今日 / 发现 / 全局搜索
→ 标的研究工作区
→ 阅读当前判断、反证、失效条件和数据日期
→ 在绑定报告的 Chat 中追问
→ 创建模拟订单草稿
→ 交易前确定性规则与组合影响检查
→ 用户独立确认
→ 组合中的委托、成交、持仓与盈亏
→ 到期任务或论文变化通知
→ 复盘原始判断和实际结果
```

### 8.2 已有持仓复核

```text
组合
→ 发现某持仓观点变化
→ 打开该标的研究版本差异
→ 查看失效条件是否触发
→ 追问或打开减仓草稿
→ 检查 T+1、可卖数量、费用和集中度
→ 用户决定是否确认
→ 复盘与同期基准
```

### 8.3 数据降级

```text
页面显示最近成功版本与真实截止时间
→ 明确缺失来源和受影响结论
→ 当前行情相关确认入口关闭
→ 用户仍可读历史报告、非操作性追问或查看数据状态
→ 后台刷新完成通知
→ 按当前内容重新检查
```

## 9. 关键页面设计

### 9.1 首页：今日决策工作台

首页不做市场大屏，也不做功能目录。

首屏顺序：

1. 是否存在需要立即确认、复核或等待开盘检查的事项；
2. 数据有效日期和关键降级；
3. 市场、组合、研究和证据四类仪表摘要；
4. 账户资产、基准和组合约束；
5. 需要用户决定的任务；
6. 自上次查看以来真正发生的变化；
7. 正在跟踪的论文与线索。

空闲文案：

> 暂无需要立即确认的操作。1 项论文需要复核，1 笔模拟订单等待开盘检查。

### 9.2 市场与发现：先理解市场，再进入线索

- 先给市场脉络，再给研究线索；
- 每条线索显示原因、证据覆盖、缺口和组合关系；
- 资金区域明确口径，避免“主力净流入”式确定表达；
- 点击任何资产直接进入对象研究工作区。

### 9.3 研究台：报告库，而不是空白生成器

- 默认展示活跃论文、观点变化、证据覆盖和下一检查点；
- 七个证据域持续显示完整、部分、未进入或不适用；
- 研究流水线展示主数据、ContextPack、多 Agent 反证、论文、交易前检查和复盘；
- 正式 Provider 未配置时明确显示“未运行”，不能用 Demo 结构化输出冒充正式会诊；
- 自选、研究队列和历史版本在同一工作域内渐进展开。

### 9.4 标的研究：原始事实与 AI 综合同时可见

首屏顺序：

1. 价格、持仓、行情时点和报告身份；
2. 当前研究判断与证据覆盖；
3. 估值、现金流、相对强弱和组合暴露等关键事实；
4. 支持与反对证据；
5. 失效条件；
6. 当前组合影响；
7. 证据账本；
8. ContextPack、Agent 和审计。

“置信度”改为“证据覆盖”。尚未完成正式前瞻校准的模型数字降级为 Demo 输出，并明确不可用于交易判断，避免用户把伪精确数字等同于成功概率。

### 9.5 模拟交易：组合中的连续动作

模拟交易不再拥有独立首页；它进入“组合”和订单抽屉。

确认前持续显示：

- 用户模拟账户环境；
- 标的、方向和数量；
- 权威行情与有效时间；
- 整手、T+1、停牌、涨跌停和可卖数量；
- 预计金额、费用和滑点；
- 操作后现金、单标的与行业仓位；
- 假设下跌 10% 的账户影响；
- AI 软建议与用户最终选择的差异；
- 明确“不会发送到券商”。

### 9.6 组合：账户、订单、约束和观点变化

- 账户选择器持续显示“用户模拟 / 外部记录”；
- 系统影子账户不出现在普通组合中；
- 资产曲线与基准、现金、费用、最大回撤同屏；
- 持仓表把“当前 AI 观点相对建仓时的变化”作为一等字段；
- 委托生命周期和成交费用不藏在二级管理页。
- 上一交易日盈亏、累计超额、可用现金、待占用资金和最大行业暴露形成持续约束带。

### 9.7 复盘：客观事实，而非课程

复盘回答：

- 当时看到了什么；
- AI 的判断是什么；
- 用户采纳、部分采纳、拒绝还是逆建议；
- 持有期间最大浮盈与浮亏；
- 失效条件是否触发；
- 相对基准结果；
- 哪条证据后来发生变化。

不输出“你应该学习某课程”之类的教学建议。

## 10. 状态设计

| 状态 | 页面行为 | 用户可做什么 |
|---|---|---|
| 正常 | 完整内容与权限 | 研究、追问、检查、确认 |
| 空数据 | 解释为什么空，不放示例填充 | 搜索、创建账户、稍后重试 |
| 加载 | 展示真实阶段、后台继续、取消 | 离开页面，等待通知 |
| 降级 | 保留最近成功内容，标出缺失和影响 | 阅读、非操作性追问、查看状态 |
| 错误 | 保留已完成步骤和上次版本 | 安全重试、查看原因 |
| 后台任务 | 内容仍可浏览，右下角显示进度 | 打开动态中心、取消或离开 |

关键要求：

- 错误不暴露原始堆栈和敏感信息；
- 加载不锁住页面；
- 输入、标的、账户、方向或数量变化后，上次交易前检查立即失效；
- Historical Demo 使用贯穿全页的“历史演示 · 仅研究”横幅；
- 数据状态、任务状态、权限和来源环境不共用一个颜色标签。

## 12. 视觉方向：Professional Workbench 03

### 12.1 品牌概念：Evidence Trace / Quiet Signal

QuantLab 不是一个有金融皮肤的聊天助手，而是一件“温暖的证据仪器”。整体比例是：

> 70% 温暖编辑阅读，30% 精密金融仪器。

核心视觉语法：

- 线：数据、研究和决策的连续路径；
- 点：一条可引用的事实或数据来源；
- 断口：缺失、过期、代理口径或失败；
- 菱形：AI 整理后的判断；
- 方形：只有用户能完成的确认闸门；
- 六边形：Agent、后台任务和运行系统。

所有线条必须满足一条规则：像数据时就编码真实状态；纯装饰时只能位于非数据背景，并保持低对比度，不能被误读成行情走势。

### 12.2 Evidence Gate 标志

新的 Q 不是完整闭合的圆：

- 外环代表市场事实；
- 内环代表当前证据边界；
- 菱形代表 AI 判断；
- 开放尾线指向铜色方形，代表用户确认；
- 没有用户确认时，路径不会自行闭合。

它避免放大镜、AI 星芒、原子轨道和大脑等通用符号，小尺寸版本仍保留开放 Q 与确认方形。

### 12.3 色彩分工

| 角色 | 色彩 | 用途 |
|---|---|---|
| Rice Canvas | `#F1EEE6` | 长时间阅读的温暖画布 |
| Reading Surface | `#FBFAF6` | 报告、票据和内容正文 |
| Carbon Ink | `#242520` | 主要文字与精密图形 |
| Quant Iron | `#425B74` | 品牌、研究、导航、普通主操作 |
| Gate Copper | `#A65338` | 用户最终确认、Evidence Gate 尾端 |
| AI Violet | `#6B6488` | AI 判断与反证关系 |
| Gain Red | `#B44332` | 中国市场上涨，只用于价格域 |
| Loss Green | `#2E6B58` | 中国市场下跌，只用于价格域 |
| Review Amber | `#AA7628` | 部分可用、待复核和软阈值 |

铁蓝承担品牌，不再由赤陶色同时承担品牌、按钮和上涨。铜色只在用户需要作出不可替代的选择时出现。红绿始终配合正负号、文字和线型，不作为唯一编码。

### 12.4 字体系统

原型使用 Windows 本地字体，不复制大型字体文件，也不依赖在线字体服务：

| 语义 | 字体 |
|---|---|
| UI 与长正文 | Noto Sans SC / Microsoft YaHei UI / Segoe UI Variable Text |
| 页面标题 | Noto Sans SC / Microsoft YaHei UI；使用 400/500 实重 |
| AI 判断与投资论文 | Noto Serif SC / STZhongsong / STSong |
| 金额、比例与行情 | Bahnschrift，tabular numbers |
| Run ID、状态与坐标 | Cascadia Mono / Cascadia Code |

衬线体不再给所有页面套“温暖滤镜”，只代表“这是 AI 或用户写下的一条判断”。桌面正文基线为 16px，连续阅读内容通常为 14px，关键状态与操作信息通常为 12–13.5px；8–10px 仅保留给编号、角标与原型坐标。中文标题避免 Light 字重，主要页面标题使用 500 实重，弱文字提高对比度；页面不在文字上方叠加噪点，也不强制 `geometricPrecision`，让 Windows 浏览器保留正常 hinting。视觉验收同时使用 DPR 2 首屏预览和 DPR 1 全页结构检查，避免把长图缩放造成的低清观感误判为产品字体问题。

### 12.5 五种专属可视化

1. **Decision Atlas**：首页把数据、论文、组合和任务汇入当前决策场；断线表示缺口，中心只回答“现在是否需要行动”。
2. **Market Topology**：发现页用等高线、风险轴和行业节点表达市场宽度与活跃度，不把普通柱图包装成“主力资金”。
3. **Evidence Constellation**：研究页把支持、反对和缺口同时汇入中央判断；悬停或键盘聚焦证据卡时，对应节点联动。
4. **Trade Folio**：交易前检查用同一条仓位带显示操作前、操作后和 30% 阈值；金额、费用、现金、集中度和下跌影响随方向与数量实时重算。
5. **Evidence Seal**：进入确认阶段时印记落位；只有用户勾选确认并提交后，方形由空心变实心。它不使用庆祝、彩屑或收益暗示。

净值图继续保留账户主线、基准短虚线、费用口径和时间范围。数据缺口必须真正断开，不能用插值跨过不可用区间。

### 12.6 Quiet Signal 动效

动效只有三种原语：

- **Trace**：证据路径从来源向判断绘制；
- **Knot**：节点在数据或状态完成后稳定落位；
- **Seal**：用户确认后进入账本。

规则：

- 页面切换优先使用 View Transitions API 的交叉淡化，回退为普通淡入；
- 图表和证据线只在首次进入或数据范围变化时绘制；
- Ambient Field 最多六条确定性等高线，15fps，DPR 不超过 1.5；
- 页面隐藏时暂停，宽度低于 760px、`saveData` 或 `prefers-reduced-motion` 时关闭；
- 降级和错误保持静止，不用动画美化问题；
- 不做金额滚动、无限漂浮、庆祝彩屑或营销式按钮扫光。

### 12.7 与 Claude 气质的边界

保留 Claude 的温暖、克制、低疲劳和可阅读性，但主动改变识别来源：

- 主色是铁蓝，铜色只代表用户确认；
- 页面身份使用邓线，衬线只属于判断和论文；
- 视觉个性来自证据线、断口、坐标、账本网格和确认闸门；
- 不依赖“米白 + 大宋体 + 赤陶按钮 + 圆角卡片”形成品牌；
- 专业空间是完整暗色仪器环境，侧栏、导航、Canvas 和状态色同步切换。

## 14. 关键设计如何解决用户问题

| 用户问题 | 设计决定 | 解决方式 |
|---|---|---|
| 不知道从哪里开始 | 今日只编排待办、变化和线索 | 先回答“是否需要行动” |
| 研究、Chat、交易割裂 | 标的工作区 + 绑定 Chat + 订单抽屉 | 上下文不丢失，减少重复输入 |
| 容易把 AI 当确定指令 | 当前研究判断、反证、失效条件、证据等级 | 把不确定性放到首屏 |
| 不知道错误原因 | 状态说明缺口、影响、未发生事项和恢复条件 | 用户能判断等待、重试或停止 |
| 容易混淆 Demo、模拟和正式成绩 | 账户/环境持续标识 + 独立专业空间 | 防止证据和收益误读 |
| 专业状态太多 | 对象级审计渐进展开，全局能力进入专业空间 | 普通流程简单，证据仍可达 |
| 模拟下单像券商 | “订单草稿 → 检查 → 用户确认”，持续写明不连接券商 | 保留用户最终控制权 |
| 窄屏页面只能纵向堆叠 | 底部导航、全屏 sheet、持仓卡片 | 围绕移动任务重新编排 |
| 缺少帮助 | 任务型帮助中心 + 上下文帮助 | 在产生疑问的地方解释 |

## 16. 下一阶段建议

本轮不建议直接大规模改写 Streamlit。

下一步应先做：

1. 用 5–8 个真实任务做可用性测试：发现标的、理解报告、处理降级、创建模拟订单、查看持仓、完成复盘；
2. 确认“五个稳定工作域 + 对象工作区”是否符合真实使用习惯；
3. 修正当前 UI 数据契约、错误原因、本地化和状态优先级问题；
4. 建立前端对象模型与状态契约，再决定继续改造 Streamlit 还是迁移到独立 Web 前端；
5. 生产实现时复用现有金融规则、账本、Job、证据和审计能力，不另造一套业务逻辑。

达到这些条件后，再按“今日 → 研究工作区 → 订单检查 → 组合 → 复盘”的顺序分阶段落地。
